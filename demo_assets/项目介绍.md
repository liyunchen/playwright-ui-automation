## 一、简历条目（可直接贴，建议保留 5 条）

**项目名称：** QA 测试平台 UI 自动化测试体系建设（从 0 主导）

**技术栈：** Python · Playwright · Pytest · Allure · Requests · Jenkins / Zadig

**项目背景：** 团队使用自研 QA 测试平台管理用例资产与环境，但平台自身缺乏自动化验证手段，功能迭代依赖人工点测，回归一次约半天且易漏测。目标是搭建一套针对平台自身的 UI 自动化体系，在 CI 中定时回归并推送报告。

**个人职责与成果：**

1. **从 0 搭建三层自动化架构**：设计 `pages / code_testcases / common` 分层，沉淀登录、项目、用例、接口、环境 5 个页面对象模块；用例层仅做业务编排，定位器与操作全部下沉，遵循 Page Object 规范。

2. **落地「UI + 接口」双重校验机制**：通过 Playwright 网络监听在操作真实 UI 的同时捕获后端接口响应，并以接口数据做断言（如项目概览接口应返回 22 手工用例 / 342 接口定义 / 63% 通过率），将断言从「页面文案是否正确」升级为「接口数据是否真实」，显著降低前端改版导致的误判。

3. **实现接口断言模板化机制**：设计 JSON 模板 + 通配符递归匹配校验器（支持 `*` / `["*"]` / `{"*":"*"}`），断言文件名由用例名自动推导，接口变更时仅需改模板、不动代码。

4. **提升执行稳定性与效率**：引入 session 级登录态复用（`storage_state` 落盘），29 个用例整体执行 5 分 42 秒（含录像）；针对平台自研树组件、Tab 懒渲染、零尺寸残留节点等 6 类真实 DOM 陷阱逐个建立定位策略，用例通过率 100%。

5. **完善工程化与安全规范**：全量注册业务 marker 支持模块级过滤；实现断言失败自动全页截图并回传 Allure；将全部账号口令从代码剥离至环境变量注入（含 4 个飞书 webhook），消除明文凭证入库风险。

## 四、可能被追问的技术问题

**Q：为什么不用 Selenium 而选 Playwright？**
A：auto-waiting 机制可替代显式 sleep，减少等待逻辑的脆弱性；内置网络监听，能直接捕获接口响应实现双重校验；并发性能与多浏览器一致性更好。

**Q：网络监听捕获接口响应可靠吗？遇到过什么问题？**
A：遇到过两类真实问题。一是 401 失败响应会触发页面跳转，导致 Playwright 无法再读取响应体（`Response body is not available for a response that was navigated away from`），这种情况下改用状态码断言；二是平台所有 GET 请求都追加 `?_t=<毫秒>` 时间戳，匹配路径前必须先剥掉查询串，否则永远匹配不到。

**Q：接口 data 字段结构不稳定怎么处理？**
A：平台有的接口 `data` 直接是数组，有的包装成 `{items, total}`。我在断言里做了类型判断兼容两种形态，避免因结构差异误判失败。

**Q：登录态复用怎么实现的？为什么不每次都登录？**
A：用 Playwright 的 `storage_state()` 在 session 级夹具里登录一次并落盘，后续用例通过该状态创建 context。好处是快（省掉每例 3-5 秒登录），也降低了登录页元素变动带来的脆弱性——登录页一改，只需要修一处。

**Q：注意不要在 fixture 里嵌套 sync_playwright？**
A：对，这是踩过的坑。session 级已有 browser fixture，再嵌套 `sync_playwright()` 会触发事件循环冲突，报 `Sync API inside asyncio loop`。正确做法是复用 browser 另开 context。

**Q：用例怎么保证不脆弱？**
A：三条原则。一是定位器全部来自实测而非推测，比如我用 evaluate 逐个查元素的 class、尺寸、可见性后才写定位器；二是优先用语义化定位（`get_by_text`、`get_by_role`）并配合 `exact=True` 规避 strict mode；三是动态内容不断言固定文案，比如接口搜索是前端过滤不重新发请求，我就改成对比过滤前后的可见条目数变化。

**Q：平台有哪些 DOM 陷阱？**
A：实测踩到 6 类：登录页「登录」与「使用飞书登录」同名需精确匹配；接口目录用的是自研树组件 `.tree-item.tree-api` 而非 Element Plus；数据管理页是 Tab 布局且存在零尺寸的残留 tab 节点；错误提示是自动消失的 toast 不可作文案断言；目录树虚拟渲染导致数 DOM 节点不可靠；演示环境数据定期重置会弹提示拦截操作。

**Q：为什么把口令从代码里移出去？**
A：早期 YAML 里明文存了 7 组账号密码，Jenkinsfile 里还有 4 个飞书 webhook token，简历是公开材料，这类凭证泄露风险高。改成 `${VAR}` 占位符 + `.env` 注入，`.env` 已在 gitignore 中；同时支持环境变量覆盖地址和账号，多环境切换不用改代码。
